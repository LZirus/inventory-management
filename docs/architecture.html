Catalyst Components: Systemarchitektur

Factory Inventory Management Demo. Vue-3-Single-Page-App spricht per REST mit einem FastAPI-Backend, das alle Daten beim Start aus JSON-Dateien in den Speicher lädt. Keine Datenbank, keine Authentifizierung.

Systemüberblick

Tech-Stack

Frontend

Vue 3 + Vite

  • Vue 3.4, überwiegend Composition API
  • Vue Router 4 (History-Modus)
  • Axios für REST-Aufrufe
  • Charts als eigenes SVG, Layout mit CSS Grid
  • i18n selbstgebaut: Englisch und Japanisch
Backend

FastAPI + Uvicorn

  • Python ≥ 3.11, Paketverwaltung mit uv
  • Pydantic-Modelle validieren jede Antwort
  • Filterung komplett im Speicher
  • Tests: pytest + FastAPI TestClient
Daten

JSON-Dateien

  • 7 Dateien unter server/data/
  • Beim Serverstart einmal geladen
  • Keine Persistenz: Änderungen gehen beim Neustart verloren
  • Neu erzeugbar mit generate_data.py

Datenfluss am Beispiel eines Filters

  1. Nutzer wählt in der FilterBar z. B. Warehouse „San Francisco“.
  2. useFilters() hält den Zustand als Singleton-Refs; alle Seiten teilen ihn.
  3. Die Seite (z. B. Dashboard.vue) reagiert per watch und ruft getCurrentFilters().
  4. api.js lässt "all"-Werte weg und baut ?warehouse=…&category=…&status=…&month=….
  5. FastAPI filtert die Listen im Speicher mit apply_filters und filter_by_month.
  6. Pydantic validiert gegen das response_model, die Antwort geht als JSON zurück.
  7. Die Seite legt Rohdaten in refs ab; KPIs und Charts sind computed-Werte darauf.

Auffälligkeiten beim Erkunden

Tasks und Purchase Orders fehlen im Backend. api.js ruft /api/tasks und /api/purchase-orders auf, main.py definiert diese Routen nicht. Ergebnis: 404 in der Konsole beim Laden der App.
Reports.vue fällt aus dem Muster. Options API statt Composition API, Axios direkt mit fest verdrahteter URL statt api.js, keine globalen Filter, kein i18n, viele console.log-Aufrufe.
Backlog.vue ist nicht erreichbar. Die Komponente existiert, hat aber weder Route in main.js noch Eintrag in der Navigation.
